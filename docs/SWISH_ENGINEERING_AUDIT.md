## Five highest-priority verified findings
1. **Critical tenant isolation:** authenticated membership INSERT checks only `user_id = auth.uid()`, allowing self-enrolment with an arbitrary tenant ID and role. The SECURITY DEFINER `swish_provision_tenant(uuid,text,text)` has PUBLIC execute, no `auth.uid()` check, and no fixed search_path. These undermine every downstream membership check.
2. **Critical connector boundary:** `has_column_privilege` confirms authenticated SELECT/UPDATE and anon SELECT permission on `credential_ref`. RLS restricts rows, but does not exclude secret columns; safe client selection is not authorization. All four observed credential rows have the `enc:v1` prefix; plaintext was NOT observed. Prefix inspection does not prove successful decryption.
3. **Niche/build failure:** NicheId omits `tech`; production gate lists five products while routing/builds/tests expect ten. Catch-all and precious-metal specialist lists overlap among niches. Routing uses substring `includes('coin')`. Build script requires missing `niche-modules.json`; workflow requires missing `scripts/verify-niche-module.js`. Clothing import removal strings contain literal `\\n`, not newlines. app.config.js does not select a reduced Expo Router root. Home statically imports other niche screens.
4. **Inventory/data consistency:** explicitly empty item/count specialist filters fall through to all-tenant data. useInventory depends on unsupported Realtime; no periodic polling. AppContext does not discard late tenant responses on account change. listingService emits itemStatus without declaring it in ListingWithItem; UI counts and rows disagree, and live rows omit media.
5. **Lifecycle integrity:** read-only SQL found 11 active/live listings linked to sold/fulfilled/completed items. Sync treats missing eBay listings as ended even if fetching failed, and updates every eBay listing for an item instead of the exact external listing. No duplicate external-listing groups and no cross-tenant item/listing links were found.

3. Make empty filters fail closed, add account/niche request fencing and polling, unify listing lifecycle classification/counts/media, preserve stable IDs and specifics.
4. Generate reduced route trees for each supported branded app, choose the root in Expo config, reject cross-product navigation, gate workflow on tests and genuine APK metadata/signature inspection. Unknown/unimplemented distributables must fail clearly rather than ship another product.
5. Harden sync against partial fetches, exact listing targeting and stale status; stop scope narrowing. Repair generation/editor issues without changing eBay listing architecture or AI model.
