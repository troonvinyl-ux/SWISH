# SWISH specialist intelligence — controlled implementation report
Date: 2026-10-30. Scope: researched specialist foundation and shared vertical-slice extensions. **Not the final production acceptance of all ten applications.**

## A. Audit and research findings
Inspected the project structure and representative entry/routing, AppContext/auth consumption, specialist/niche/package registries, shared capture, inventory services, editor service/hook, listing generation/save/publish, market-value, commercial/profit engines, Expo packaging, CI and existing test sources. The package manifest read was denied. There is no command-execution, device, artifact, GitHub-commit or separate WEBSITE-workspace tool in this session. No comprehensive runtime baseline can be claimed.

Verified source defects: bicycles/fossils/beauty/tech/surplus identification fell back to a generic system prompt; the common result schema was coin-shaped; server valuation product mapping recognised only older products and treated generic curiosities as Coins; generated item specifics were discarded by saveListing; the generic capture had no follow-up review, durable draft or duplicate-safe photo retry; stock detail defaulted unknown niches to coin fields. Existing profit code also includes inconsistent fee assumptions and unsupported time-to-sale defaults. The new buying panel does not rely on those defaults.

Research used public specialist/manufacturer/marketplace guidance, not proprietary sales access. Sources below are verified destinations, not evidence automatically retrieved for individual scanned items. Competition examples are market-context comparisons, not independently benchmarked feature/performance claims.

## B. Implemented source functionality
- `shared/specialistIntelligence.ts`: ten substantive, versioned expertise profiles, field schemas, taxonomy, condition/value/listing rules, sourcing checklists, source destinations and shared validation. Product/specialist identity remains solely in `niche-modules.json`.
- `swish-identify`: canonical server specialist validation, membership remains required, bounded image/context input, specialist output schema for non-coins, profile-led recognition, image assessment within the same AI call, targeted unresolved follow-ups, no photo-based authentication/fitment/valuation certification, request timeout. Coin/MX/clothing established model retained; newly specialised non-coin paths use default Gemini 3 Flash. Existing coin Numista/Islamic and second-pass tools retained. Failure quota refund now compare-and-swap and no longer references nonexistent updated_at.
- `/capture`: specialist selection restricted to the active product; part mode for bikes/MX and lot evidence for surplus; camera/gallery permission feedback; metadata-only low-resolution preflight; original-image retention on native; account-scoped serialised local autosave; editable proposals/fields; useful follow-ups; retry with supplied answers; save canonical ID before upload; photo retry never inserts another inventory item.
- Buying panel: calls existing market research only on request; separates manual price scenarios from sold-backed evidence; fees charged against sale plus buyer postage, seller postage separately; repair/packaging/other/labour costs; conservative maximum buy and break-even; budgets/ROI/profit/holding preferences; explicit unknown time to sell; lot yield sensitivity. Score capped below 50 for weak evidence or manual price overrides; known safety risks score zero. No automated purchase/trading/publishing.
- Saved stock detail: niche-aware editable specialist fields, bounded user-correction history and optimistic concurrency across tenant/niche-scoped writes; generic objects no longer default to coin field blocks. The existing listing editor remains authoritative for marketplace copy/category/specifics.
- Listing generation: uses researched per-niche content rules and evidenced item-specific mapping; retains proper non-coin terminology; MX components avoid complete-bike category/title structure; non-running no longer accidentally becomes Runs; nested metadata not converted to object-object text.
- Atomic draft RPC and saveListing integration: draft plus merged specifics in one authorised transaction; item lock serialises retries; existing seller draft/specific values preserved; no speculative category IDs saved. Existing Taxonomy, edit, OAuth and publication infrastructure reused.
- New-niche home cards now display actual sourcing checks and specialist focus, rather than just a colour/name change. Existing dedicated homes were not replaced.
